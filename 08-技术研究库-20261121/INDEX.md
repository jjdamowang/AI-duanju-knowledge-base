# 技术研究库 INDEX

2026-11-21 Jason 定：长期机制「技术资料持续学习与能力优化」。本库沉淀经审核的技术研究结论，与短剧案例知识库（duanju-kb）分开；技术研究不改正式方法库、不改已验收架构、不替换现有技术路线（替换须 Jason 批准）。

## 收录范围

与短剧制作相关的：技术文章、视频、模型、软件、工作流、插件、节点、提示词、教程、测试结果、失败案例。

## 处理流程（每份资料）

1. 识别资料类型及其解决的问题。
2. 核实来源、版本、发布日期和可信度。
3. 分析技术原理、使用条件、限制和适用范围。
4. 区分官方能力说明、第三方实测、用户经验和未经验证的宣传。
5. 对照当前工作台架构，判断能否解决现有问题。
6. 分析成本、部署难度、硬件要求、兼容性和维护成本。
7. 判断是否值得开展测试，并提出最低成本验证方案。
8. 将经过审核的结论沉淀到本库。

## 每份研究的必填输出

技术名称和版本／原始来源及链接／解决的问题／技术原理／使用条件及硬件要求／优点与局限／实际测试证据／与当前工作台的关系／可替代的现有方案／成本及维护负担／推荐结论／是否建议纳入正式生产流程。

## 结论分级

- A：已经实际验证，可以考虑投入生产。
- B：原理和资料基本可靠，等待实际测试。
- C：有一定参考价值，但证据不足。
- D：不适合当前项目，或存在明显缺陷。

## 纪律

- 不盲目追逐新模型、新工具、新技术；不因新颖就认为比现有方案好。
- 不把技术宣传当作实际测试结果。
- 未经 Jason 批准，不替换现有技术路线。
- 不为增加内容而重复收录同类信息；收录前先查本库 INDEX 有无同类条目。
- 持续检查与已有知识是否冲突、是否重复、是否需要更新；发现冲突在新条目中标注并回指旧条目。
- 发现现有架构明显缺陷时，主动提出改进建议，但不擅自修改已验收架构（3A）。
