## 一、模块主链与协作总图

主链顺序（编号为固定骨架）：

```
M1 商品资料与事实核验
 → M2 商品与故事匹配 ──┐（与 M3 并行，见 §二）
 → M3 观众心理与商业策划┘→ 会签点 S1
 → M4 人物与人性设计 ⇄ M5 故事结构设计（迭代，见 §二）→ 骨架确认（人闸）
 → M6 剧本创作
 → M7 编剧质量审核 ──不过→ 回 M6（结构问题回 M5/M4，见 §三交接表备注）
 → M8 AI导演与视听叙事 ──┐（与 M11 并行设计，见 §二）
 → M9 分镜和镜头拆解 ────┤
 → M10 AI视频制作可实现性评估 ⇄ M9（回馈回路，见 §二）→ 闸口A/B
 → 〔生成执行：按时间轴排产，非独立模块，见文档头待解决问题 1〕
 → M11 声音设计（设计段与 M8/M9 并行；实测段是 M9 定稿的前置，见 §二）
 → M12 后期剪辑与镜头衔接
 → M13 成片质量验收（人闸）→ 归档（见 05 文档）
```

横切机制（不占主链位置，全程生效）：

- **四问题质量链＋失败阶梯**：任一模块发现的失败，按「诊断（B1 六类归类）→ L1 局部修改 → L2 替代镜头/替代拍法 → L3 重生成」的顺序处置（问题四 B2），处置结果回流到问题产生的模块修，不许在下游就地凑合（整合稿 §1.1）。
- **版本管理**：一切交接物带版本号，一切修改走变更单（见 §四与 05 文档）。本稿只定协作动作，版本规则本体在 05 文档。

## 二、并行与顺序判定

### 2.1 可以并行的工作（附同步点）

| 并行组合 | 为什么可以并行 | 同步点（并行段的收口） |
| --- | --- | --- |
| M2 ∥ M3 | M2 回答「商品能以什么功能进入故事」，M3 回答「观众为什么看、为什么信、为什么买」，两者都以 M1 的已确认事实为共同输入，互不以对方产出为前置 | **会签点 S1**：M2 的商品功能位与出现时机约束、M3 的说服路径与禁用手段清单，两份文件互相引用后才放行 M4/M5；冲突（如 M2 想让商品承担关键情节功能、M3 判定该位置说服上不成立）在此点裁决，不带入下游 |
| M4 ⇄ M5（迭代并行） | 人物动机决定事件是否成立，事件压力又反过来检验人物；串行写完人物再写故事，必然出现「骨架需要人物做他不会做的事」 | 迭代方式见 2.3；收口＝骨架确认人闸 |
| M11（设计段）∥ M8、M9 | 声音设计若等分镜定稿才开始，BGM 进出点、停顿格、声音桥就只能事后硬贴，与「声音与画面同步设计」（任务书 §四.6）冲突。M11 设计段的输入是 M6 定稿剧本的台词与节拍、M4 的人物声音性格、M8 的逐场情绪节拍——这些在 M8 启动时即陆续可用，不必等 M9 完成 | 三个同步点见 2.4 |
| M10 预检一 ∥ M6 创作准备 | 预检一（场级粗筛）作用于 M5 骨架而非 M6 全本：骨架确认后即可按场标风险（问题三 §4.1），其产出（场级风险标注）是 M9 的输入，与 M6 写全本互不阻塞 | 粗筛标注随骨架一同交付 M6/M9，M6 写作时可查阅但不受其约束（粗筛只约束拍法准备，不约束台词） |

### 2.2 必须串行的硬顺序（逐条给理由）

| # | 硬顺序 | 理由 |
| --- | --- | --- |
| H1 | M1 中某项事实未确认 → M6 不得把该事实写成台词或画面信息（只能留占位符） | 未核实的价格、功效、出版信息一旦写进台词，会沿 M8→M9→生成全链扩散，后期清洗成本远高于前期等待；且健康类内容把未确认事实写成宣称即构成合规风险（任务书 §四.3）。占位符写法：`〔待核实：实际售价〕`，M7 审核时见占位符未清零即不放行 |
| H2 | M5 骨架经确认（人闸）→ 才进 M6 全本创作 | 既有强制闸口（创作测试方案）：骨架九项未确认就写全本，结构问题会在全本层放大，返工量是骨架层的数倍 |
| H3 | M7 审核通过 → 才进 M8 | M8/M9 的全部工作量建立在剧本成立的前提上；逻辑或人物问题在导演阶段发现，只能回炉剧本，导演与分镜工时全废。对应整合稿闸口逻辑：前环未解决不得推给下一环 |
| H4 | M11 实测段（旁白/台词录音完成并量出实测时长）→ M9 时长字段定稿（仅旁白线） | 问题四 A2 方法 1：画面时长服从声音实测时长，先定画面再凑声音必然要变速或留空音。M9 可以先出时长以外的全部字段，时长列在实测回填前标「待实测」，不得凭估算锁定 |
| H5 | M10 评估过闸（闸口 A：逐镜有级、C 级替代设计齐全并重打分 ≤B；闸口 B：意图卡齐备、歧义预检通过）→ 才进生成执行 | 整合稿 §1.3 原文口径。C 级镜头直接生成等于拿 GPU 预算赌已知的硬伤区（三人同框、手递手、文字面） |
| H6 | M9 时间轴锁定（★字段全填、已生成镜 ☆字段回填齐）→ M12 才做拼前预演与正式拼接 | 问题四 A7/A8：拼前预演的对象就是锁定版时间轴；时间轴未锁定就拼，等于剪辑师凭记忆接缝，是「单镜合格、组合不可用」的主要来源 |
| H7 | M13 验收通过（Jason 人闸）→ 才算交付 | 既有拍板分工：成片验收属用户拍板项；JJ 自审通过只到「可送审」状态 |

### 2.3 M4 与 M5 的迭代规则

1. 迭代单位是「一轮」：M4 出人物小传修订 → M5 据此调骨架一场 → M4 复核该场人物行为是否成立，三件算一轮并登记（登记表字段见 05 文档修改记录）。
2. 轮次上限 2 轮。第 2 轮后仍有核心冲突（人物动机撑不起骨架主事件，或骨架主事件逼人物做不符合其人性的事），停止迭代，回骨架层重做骨架（沿用「补丁超两轮停下重做」的既有口径，向设计环节迁移，属待验证假设 3）。
3. 迭代中冻结项：M2/M3 在 S1 会签的商品功能位与说服约束，M4/M5 迭代无权改动；认为必须改的，走变更单回 S1 重新会签。

### 2.4 M11 与 M8/M9 的三个同步点

| 同步点 | 时机 | 动作 | 产物 |
| --- | --- | --- | --- |
| SP-1 意图对齐 | M8 启动时 | M8 把逐场情绪节拍与「观众此时应知道/不应知道」清单交给 M11；M11 据此出声音设计草案（每场的声音基调、BGM 进出预定位置、停顿格位置、声音桥候选接缝） | 声音设计草案 v0.x，与 M8 意图卡同版本号段登记 |
| SP-2 时长回填 | M11 旁白/台词录音完成时 | M11 把每段旁白的实测时长按段落号回填给 M9；M9 据实测值定稿时长字段并复核台词容量（4.2 字/秒，问题二实测口径，经整合稿 C6 确认为权威出处） | 时间轴时长列由「待实测」转「已定稿」；超时长段落当场标出，由 M9 拆镜或 M6 改词（二选一，看哪边错，问题四 B2 L1 口径） |
| SP-3 定稿会签 | M9 分镜定稿时 | M9 时间轴声音组字段（音频来源、台词相对位置、环境声与音效点、BGM 进出与 duck 标记，问题四 A8）与 M11 声音设计表的 cue 逐条对齐：每个 cue 必须能在时间轴上找到对应镜号，每个有声镜必须有 cue 或显式标「无台词」 | 分镜定稿三件套（整合稿节点 3）＋声音设计定稿，会签后双方版本号锁定对应关系，登记在版本对应表（05 文档） |

### 2.5 M10 对 M9 的回馈回路

1. M9 交分镜表＋预剪辑时间轴 → M10 执行预检二（逐镜七项打分落级，问题三 §一）。
2. 回馈只有三种出口：
   - **通过**：过闸口 A/B，进生成排产。
   - **回 M9 改拍法**：C 级镜（及一票升级镜）由 M9 按五条替代通道（拆镜／换景别／换叙事通道／实拍替代／后期合成）出替代设计，过信息等价检查（剧情信息＋情绪任务逐条在，问题三 §3.2），重新打分；**回馈单只许指向分镜四样（拆合、景别、通道、通道分配），不许要求改故事**（问题三 §4.2 硬边界）。
   - **冻结上报**：改拍法后仍 ≥C 或信息等价检查不过的镜，冻结为「难度顶格报告」报 Jason 拍板（问题三 §4.3），M9/M10 均无权自行改故事或降格硬拍。
3. 回路计数：同一镜在 M9⇄M10 之间往返计入该镜的处置计数，与生成阶段的 L1/L3 处置合并计数（整合稿 C3：同方案处置经 2 次复验仍不过，强制升级处置或重做该镜设计）。

| M7→M8 | 审核通过单：八类审核（故事逻辑/人物行为/对白/商业说服力/合规/视听预检/可实现性预检/其他）的问题清单及关闭状态 | 是否存在未关闭的「阻断」级问题（有则不得签收）；被驳回的问题是否附理由（驳回不等于消失，留痕供回归检查） |

| M9→M10 | 分镜表＋预剪辑时间轴（★字段全填，问题四 A8）＋每镜意图卡（纯信息镜可只填剧情任务与预期读法两栏，整合稿节点 3） | ★字段有无缺项；每镜是否带「来源段落」绑定字段（§4.1）；时长列旁白线是否已实测回填（H4） |
| M10→M9（回馈） | 评估回馈单：逐镜七项分与等级、C 级镜的替代设计要求（只指向分镜四样）、信息等价检查结果、预检声明行（替代 N 处、未改动剧情信息） | 声明行是否附表；信息等价检查不过的镜是否已单独冻结上报而非混在回馈单里放行（问题三 §4.2） |
| M10→生成执行 | 排产清单：按时间轴优先级排序（锚点镜、钩子镜、商品点名镜、收尾镜先行，问题四 B5-9）、B 级试产清单（同类只试代表镜） | 试产清单是否先行（试产不过不批量，问题四 B3-2）；排产清单中是否有处于「待同步」状态的镜号（有则剔除，见 §4.3） |
| M11→M9（SP-2） | 旁白实测时长表：段落号→实测秒数→对应录音文件版本 | 段落号与剧本现行版是否一致；录音版本是否为音色槽登记的现行版本（05 文档） |
| M9＋M11→M12 | 锁定版时间轴（★全填、☆回填齐）＋声音设计定稿（cue 表）＋素材清单（每镜素材文件名＋版本号，新版新文件名） | 时间轴与声音设计表的版本号对应关系是否登记；素材清单中是否有作废版本文件混入（§4.4） |
| M12→M13 | 粗剪/成片文件＋三轨对照记录（粗剪阶段口播×画面两轨，烧字幕后三轨，问题四 A3 方法 3）＋拼前预演问题清单及处置结果 | 五形态问题（接缝跳/色调跳/声音跳/节奏跳/信息跳，问题四 A7）是否全部定级处置完毕；空音扫描（silencedetect）结果是否达标（按管线选红线，两条不混用，整合稿 C6） |
| M13→归档 | 验收包（构成见 05 文档 §六） | 版本对应表是否完整（成片所依据的每个产物版本号逐项列明） |

## 四、变更传播机制（核心）

解决的问题：剧本改一处之后，分镜、声音设计、制作方案里凡是建立在旧文本上的产物，必须能被**找全、标出、同步、复验**，且同步完成前不得进入制作。以下步骤可直接照做。

### 4.1 编号绑定体系（一切传播的前提）

三套编号，全程稳定、永不复用、永不重排：

| 编号 | 格式 | 规则 |
| --- | --- | --- |
| 剧本段落号 | `S{场次}-P{段序}`，如 S03-P07 | M6 写全本时逐段编号；一段＝一个动作节拍或一轮对白。删段时该号标「作废」保留在原位，不许后续段落递补重排（重排会打断全部分镜绑定） |
| 镜头号 | `{场次}-{镜序}`，如 3-04 | 沿用问题四 A8 时间轴镜号。每行时间轴必填扩展字段「来源段落」：列出本镜所依据的段落号（可多个）。拆镜新增镜号用后缀（3-04a、3-04b），不许插入重排 |
| 声音 cue 号 | BGM/环境声：`CUE-{场次}-{序}`；旁白段：`NB-{段落号}`（直接借用段落号绑定）；音效点：`SFX-{镜号}-{序}` | 声音设计表每条 cue 必填「绑定对象」字段：BGM/环境 cue 绑场次或镜号区间，旁白绑段落号，音效绑镜号 |

绑定关系的存放处只有两个：时间轴的「来源段落」列、声音设计表的「绑定对象」列。不另建第三张绑定表，避免三处维护不一致。

### 4.2 变更登记（任何修改的第一步）

任何人对剧本、人物设定、场景道具设定动笔修改前，先在修改记录表登记一张变更单（表结构见 05 文档 §五），必填：变更编号（CHG-日期-序号）、被改对象（类型＋编号，如「剧本段落 S03-P07」）、变更类型（台词文字／动作节拍／人物设定／场序结构／商品信息／其他）、变更前后摘要、发起人、批准人（按既有拍板分工：编剧＋导演审稿层面的修改 JJ 直接定；涉及骨架层、商品事实、方向与成本的，等 Jason 拍板）。

**没有变更单的修改视为未发生**：下游签收时发现产物与变更单对不上的，按未登记修改退回。

### 4.3 影响扫描与「待同步」状态机

变更单登记后，按以下顺序扫描影响范围：

**第一步：直接影响（查绑定）**
- 被改的是段落 → 在时间轴中查「来源段落」含该段落号的全部镜号；在声音设计表中查绑定该段落号的旁白段与 cue。
- 被改的是人物设定 → 查时间轴中出现该人物的全部镜号＋该人物的音色槽与定妆资产（资产处理见 05 文档 §三）。
- 被改的是场景/道具设定 → 查该场景全部镜号＋道具不变清单相关行（问题四 A1 方法 5）。

**第二步：间接影响（按变更类型查固定规则表）**

| 变更类型 | 必查的间接影响 |
| --- | --- |
| 台词文字变化（字数增减） | 该镜时长字段作废待重算；旁白段须重录并重新实测（回 SP-2）；口型镜的拆分点可能变化（M9 复核） |
| 动作节拍变化 | 该镜出点/入点状态（A8 连续性组）作废待重填；其前后相邻镜的接缝核对结果一并作废（接缝是两镜之间的，接缝复验范围＝受影响镜＋其相邻接缝，整合稿 §1.3 口径） |
| 场序结构变化（增删场、调序） | 全片接缝表重查；BGM cue 的进出点全部复核；钩子回查三点重做（问题四 A3 方法 4） |
| 商品信息变化 | 全部商品镜复核；M7 商业说服力与合规两类审核对该商品相关段落重新过一遍；M1 白名单同步更新 |
| 情绪节拍/强度变化 | 节拍强度曲线重连（问题四 A4 方法 3）；绑定该场的 BGM cue 与停顿格复核 |

**第三步：打标与阻断**
- 扫到的每个下游产物（镜号行、cue、资产）在其登记处把状态由「现行」改为「**待同步**」，并在备注栏填变更编号。
- **阻断规则**：M10 出排产清单时，处于「待同步」的镜号一律剔除；M12 拼前预演时，「待同步」的镜号与 cue 不得使用。阻断靠排产清单与时间轴的状态列执行，执行人是出清单的人（JJ），不是靠口头提醒。

**第四步：同步与回归复验**
- 每个「待同步」项的责任模块按新文本更新自己的产物（分镜改字段、声音改 cue、制作方案改排产），更新完把状态改为「已同步待复验」，并在变更单的同步回执栏逐项打勾。
- 复验只验受影响项＋受影响接缝（整合稿统一处置口径）：分镜项复验其字段与意图卡是否仍成立；声音项复验时长与 cue 对齐；镜头素材已生成的，受影响镜按失败阶梯重新走逐镜双道验收（整合稿节点 6）。
- 全部回执打勾且复验通过，变更单状态置「已关闭」，相关产物状态恢复「现行」。任一项未完成，变更单保持开启，下游阻断不解除。

### 4.4 旧版本冻结与作废标记

1. **冻结**：变更单开启的瞬间，被改对象的旧版本即冻结——冻结版只读，不许再在冻结版上继续改（防止「改了一半的旧版」被当成现行版交接）。
2. **新版产生**：修改在新文件中完成，按 05 文档的版本编号规则升版；新文件名带新版本号（新版新文件名，既有规矩），不覆盖旧文件。
3. **作废标记**：新版经签收成为现行版后，旧版文件做两件事——文件头状态行改为「已作废，被 vX.Y 取代，作废原因：CHG-编号」；文件移入该类对象的「历史版本」子目录。历史版本只读保留，供审计与回溯，不删除。
4. **权威目录只留现行版**：每类对象的权威存放处（05 文档 §二）根目录下只允许有一份现行版文件；签收人发现根目录有两份未标作废的同类文件，按版本冲突处理，先停交接、查版本登记表定权威，再继续。

### 4.5 一次完整变更的走查示例

剧本 S03-P07 玉珍的台词改了两句（字数增加约 20 字）：
1. 登记变更单 CHG-1121-03（对象：段落 S03-P07；类型：台词文字；批准：JJ，编剧层修改）。
2. 直接扫描：时间轴中来源段落含 S03-P07 的是镜 3-04、3-05；声音设计表中 NB-S03-P07 一段。间接扫描（台词类）：3-04 时长待重算、NB 段须重录。
3. 镜 3-04、3-05 与 NB-S03-P07 标「待同步」；若 3-04 已在排产清单中，当场剔除。
4. M11 重录 NB 段，新实测时长回填（SP-2）；M9 按新时长复核 3-04 是否需拆镜，更新时间轴并升版。
5. 复验：3-04/3-05 的意图卡与时长字段、三轨对照（该段）重过；通过后变更单关闭，三项状态恢复「现行」。

## 五、本稿未解决的问题（不掩盖）

1. 编号绑定与状态机目前是**纸面机制**：靠分镜表、声音设计表、修改记录表三张表的人工维护执行，没有工具拦截「忘了打标」。在一部 5–10 分钟长片（约 100+ 镜）的真实改稿中漏标率多高，未验证（对应待验证假设 1、2）。缓解办法只有签收检验与排产清单出单时的人工复核，已写进 §三、§4.3，但这不等于问题已解决。
2. 「生成执行」的模块归属未定（文档头待解决问题 1）：若总体架构（交付一）裁定生成执行独立成环，本稿 §二 H5、§三中 M10→生成执行的交接需相应改写。
3. M7 审核本身的多轮回归机制（审核问题如何定位、修订后如何回归检查）属交付四范围，本稿只规定了 M7 的交接物与回流去向，未展开。
