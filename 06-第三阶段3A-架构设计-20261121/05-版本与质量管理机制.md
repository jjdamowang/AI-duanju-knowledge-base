## 一、总原则

1. **单一权威**：每一类对象在任一时刻只有一份「现行版」。其余版本要么在「历史版本」子目录里标作废只读存放，要么不存在。不允许两份未标状态的同类文件并行流通（沿用既有规矩）。
2. **版本可回溯**：任何一份成片、任何一条问题记录，都必须能顺着版本号查到它所依据的剧本、分镜、声音设计分别是哪一版（靠 §六的版本对应表）。
3. **改必留痕**：一切修改先登记变更单（03 文档 §4.2），再动文件；修改记录不删、不覆盖，错误记录保留并注明更正（沿用既有留痕规矩）。
4. **状态显式**：每个受管对象带状态字段，状态只有五种：草案／现行／待同步／冻结／已作废。状态不在文件名里暗示，必须写在文件头状态行与版本登记表里，两处一致。

### 2.2 版本登记表（全项目一张）

字段：对象类型｜对象编号/名称｜当前版本号｜状态｜文件路径｜所依据的上游版本（如分镜表依据的剧本版本）｜最近变更单号｜最近修改日期。

规则：
- 每次升版、每次状态变化，当场更新登记表；登记表是签收核对的唯一依据（03 文档 §三通则）。
- 交付与归档时，登记表快照随验收包存档（§六），快照即该成片的版本对应表来源。

### 2.3 存放选项

- **本地项目目录**：全类对象的默认存放处，按 §2.1 的子目录结构组织。
- **GitHub 仓库**（`jjdamowang/AI-duanju-knowledge-base`）：可作文本类对象（剧本、设定卡、分镜表、声音设计表、登记表、台账）的异地存放与版本固定选项——每次推送的 commit SHA 即该批文档的版本指纹，审核时以 SHA 定位确切版本（已有实际使用：第二阶段研究全量提交 commit 6121d8b）。视频素材本体不入仓，仓库只登记其文件名与版本号（见文档头待解决问题 1）。
- 两个存放处并用时，必须指定一个为权威（默认本地项目目录），另一个为镜像；镜像滞后时以权威处登记表为准，不许两处各改各的。

## 四、第二轮补充（v1.1 新增）

### 4.1 素材版本与生成记录（GE 口径，对应问题一）

GE（生成执行单元，定位见 03 文档 §六）产出的素材与记录，按以下口径纳入版本管理：

1. **素材命名沿用既有规则**：素材文件名＝`{镜号}-{素材版次}`（§2.1 镜头行），如 3-04-v2.mp4。素材版次只由 GE 的生成／重生成动作递增；L1 局部修改产出的新文件同样升版次，不许覆盖原文件；实拍、静态资产、后期合成路线的产物入「素材」子目录时用同一命名规则登记，保证时间轴 ☆ 字段只认这一套文件名。
2. **生成记录字段（逐镜一条，GE 填写）**：任务单号｜批号｜镜号｜素材文件名与版次｜生成路线｜使用的模型与参数（能够获取时填写；平台不提供时标「未提供」，不许凭经验编造参数）｜生成所依据的剧本版本｜生成所依据的分镜表版本｜生成时间｜状态（成功／失败）｜失败原因（失败时填，按失败阶梯 B1 六类归类）｜处置指向（待诊断／L1 局部修改／L2 回 M9·M10 替代拍法／L3 重新生成）｜处置轮次计数（沿用统一口径，见下条）｜问题台账条目编号（失败时填，见下条）。批次级另有批头记录：批号、交接物版本清单、GE 版本一致性核对结果（03 文档 §6.4）。
3. **生成记录与问题台账的关联**：生成记录只记事实（生成了什么、依据哪一版、结果如何），不记处置结论。每条失败的生成记录，以「镜号＋素材版次」为键，在问题台账中建立对应条目（台账条目回填生成记录编号，生成记录回填台账条目编号，双向可查）；诊断、处置定级与状态流以问题台账为准。处置轮次计数与台账合并计数（同一镜同一方案下 L1 与 L3 合计，沿用已确认结论 2 与整合稿 C3），GE 不得在生成记录里另计一套次数。台账条目关闭后，处置结果摘要回填生成记录的「处置指向」栏，生成记录至此闭合。
4. **存放**：生成记录表存项目目录「素材」子目录，与素材本体同级登记；素材本体不入 GitHub 仓库（文档头待解决问题 1），生成记录表属文本类对象，可入仓固定版本。

**成片版本与数据快照的对应关系**：对应链为「成片文件版本号 → 归档包版本对应表 → 快照登记的成片版本字段 → 归因报告引用的快照集 → 建议单依据」，任一环断裂（快照查不到对应成片版本、报告引用了不存在的快照编号），该快照／报告不得作为下一轮创作的变更依据，先补登记再使用。同一作品多版成片的数据分开成集，不合并计算。

**登记**：三类反馈记录在版本登记表（§2.2）中新增对象类型「反馈记录」登记，字段沿用登记表既有字段（对象编号填快照编号／报告名／建议单号，所依据的上游版本填成片版本或所依据快照编号）。

### 4.3 成片验收归档包补记：发布与反馈登记位（对应问题二）

1. 成片验收归档包（构成见原 §六口径）在既有九项之外**新增第十项「发布与反馈登记位」**：登记该成片的发布信息占位与 F 的产出编号——数据快照编号列表、归因分析报告编号、修改建议单号。
2. **归档时该项允许为空**：成片验收发生在发布之前，归档时登记位只建空位并注明「待发布后回填」；这不构成归档不完整，不阻断 M13 验收归档。
3. **发布后回填**：发布并完成首轮数据采集后回填快照编号，后续新增快照、报告、建议单编号逐次追加；回填只追加编号，不改动归档包其他任何内容，每次回填在版本登记表留一条记录（回填日期、回填编号、回填人）。
4. 回填的编号必须与「反馈」子目录中的实际文件对得上；对不上的按登记错误处理，先更正登记再使用数据（与 §4.2 对应链规则联动）。
