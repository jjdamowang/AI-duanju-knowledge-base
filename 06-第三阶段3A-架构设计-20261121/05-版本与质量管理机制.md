## 一、总原则

1. **单一权威**：每一类对象在任一时刻只有一份「现行版」。其余版本要么在「历史版本」子目录里标作废只读存放，要么不存在。不允许两份未标状态的同类文件并行流通（沿用既有规矩）。
2. **版本可回溯**：任何一份成片、任何一条问题记录，都必须能顺着版本号查到它所依据的剧本、分镜、声音设计分别是哪一版（靠 §六的版本对应表）。
3. **改必留痕**：一切修改先登记变更单（03 文档 §4.2），再动文件；修改记录不删、不覆盖，错误记录保留并注明更正（沿用既有留痕规矩）。
4. **状态显式**：每个受管对象带状态字段，状态只有五种：草案／现行／待同步／冻结／已作废。状态不在文件名里暗示，必须写在文件头状态行与版本登记表里，两处一致。

### 2.2 版本登记表（全项目一张）

字段：对象类型｜对象编号/名称｜当前版本号｜状态｜文件路径｜所依据的上游版本（如分镜表依据的剧本版本）｜最近变更单号｜最近修改日期。

规则：
- 每次升版、每次状态变化，当场更新登记表；登记表是签收核对的唯一依据（03 文档 §三通则）。
- 交付与归档时，登记表快照随验收包存档（§六），快照即该成片的版本对应表来源。

### 2.3 存放选项

- **本地项目目录**：全类对象的默认存放处，按 §2.1 的子目录结构组织。
- **GitHub 仓库**（`jjdamowang/AI-duanju-knowledge-base`）：可作文本类对象（剧本、设定卡、分镜表、声音设计表、登记表、台账）的异地存放与版本固定选项——每次推送的 commit SHA 即该批文档的版本指纹，审核时以 SHA 定位确切版本（已有实际使用：第二阶段研究全量提交 commit 6121d8b）。视频素材本体不入仓，仓库只登记其文件名与版本号（见文档头待解决问题 1）。
- 两个存放处并用时，必须指定一个为权威（默认本地项目目录），另一个为镜像；镜像滞后时以权威处登记表为准，不许两处各改各的。

## 三、锁定资产管理（人物设定／场景道具设定／锚点资产）

### 3.1 什么叫锁定

以下资产在指定节点后进入「锁定」状态，锁定后不得随手修改：
- 人物设定卡与场景道具设定卡：M4⇄M5 迭代收口（骨架确认）时锁定。
- 五类锚点资产（定妆图/角色板、服装定义、参考音频＋音色槽、场景空镜＋光位句、道具白底图＋商品文字表）：资产锁定节点（整合稿节点 2）登记入资产表时锁定。缺一项不开拍（问题一口径）。

### 3.2 锁定后变更手续（五步，缺一不可）

1. **变更申请**：在修改记录表登记变更单，写明改什么、为什么改、申请人。口头决定不算数。
2. **影响评估**：按 03 文档 §4.3 的扫描规则列出受影响清单——涉及该人物的全部出场镜号、该人物参与的全部场次与对白段落、关联的音色槽与定妆资产，逐项判断影响范围；若变更对象是场景或道具，则列出涉及该场景／道具的全部镜号与时间轴行。评估结论写入变更单，未做影响评估的变更单不进入下一步。

> 〔恢复补写标注：以下第 2 步补完部分、第 3–5 步及锚点替换规则为 v1.2 恢复补写——依据第一轮设计口径恢复补写，原始文件未完整落盘，本次为结构恢复，不是原文恢复。〕

3. **分级批准**：按变更的影响层级定批准人。细节级变更（不触及人物动机、人物关系与故事骨架的细节调整）由 JJ 直接批准；涉及人物动机、人物关系或骨架层（事件顺序、结局、商品出现时机）的变更，必须经 Jason 批准后才生效（与骨架闸口及 03 文档 §4.2 的批准分工一致）。批准结论与批准人记入变更单，未批准的变更单不得执行修改。
4. **下游处置**：修改执行后，受影响清单中已经产出的镜头逐镜按三级处置——①作废重生：旧素材作废，按新版设定重新生成；②保留并记偏差：素材保留使用，偏差内容在问题台账登记，并在成片验收时显式说明；③冻结待拍板：一时定不了处置方式的，先冻结该镜（不得进入拼片与交付），等 Jason 拍板。每镜的处置结论回填变更单与问题台账；处置与失败阶梯的衔接（L1 局部修改／L2 换方案／L3 重新生成）按 §五台账口径执行。
5. **回归复验与关闭**：下游同步完成后，只复验受影响项与相邻接缝（受影响镜与其前后接缝、受影响段落的三轨对照），不全片重验（复验范围通则见 04 文档 §4.2）。复验通过，变更单才关闭，相关对象状态由「待同步」恢复「现行」，并更新版本登记表；复验不过，变更单保持开放，按 §五问题台账流程另开条目处理。

**锚点替换规则**：锁定锚点资产被新锚点替换时（换定妆图、换参考音频、换道具白底图等），必须在资产登记中登记新旧对应关系（旧锚点编号 → 新锚点编号、替换原因、批准人），旧锚点转入历史版本只读保存；不许无声替换，不许删除旧锚点记录。已按旧锚点生成的素材，按第 4 步三级处置逐镜处理。

## 四、第二轮补充（v1.1 新增）

### 4.1 素材版本与生成记录（GE 口径，对应问题一）

GE（生成执行单元，定位见 03 文档 §六）产出的素材与记录，按以下口径纳入版本管理：

1. **素材命名沿用既有规则**：素材文件名＝`{镜号}-{素材版次}`（§2.1 镜头行），如 3-04-v2.mp4。素材版次只由 GE 的生成／重生成动作递增；L1 局部修改产出的新文件同样升版次，不许覆盖原文件；实拍、静态资产、后期合成路线的产物入「素材」子目录时用同一命名规则登记，保证时间轴 ☆ 字段只认这一套文件名。
2. **生成记录字段（逐镜一条，GE 填写）**：任务单号｜批号｜镜号｜素材文件名与版次｜生成路线｜使用的模型与参数（能够获取时填写；平台不提供时标「未提供」，不许凭经验编造参数）｜生成所依据的剧本版本｜生成所依据的分镜表版本｜生成时间｜状态（成功／失败）｜失败原因（失败时填，按失败阶梯 B1 六类归类）｜处置指向（待诊断／L1 局部修改／L2 回 M9·M10 替代拍法／L3 重新生成）｜处置轮次计数（沿用统一口径，见下条）｜问题台账条目编号（失败时填，见下条）。批次级另有批头记录：批号、交接物版本清单、GE 版本一致性核对结果（03 文档 §6.4）。
3. **生成记录与问题台账的关联**：生成记录只记事实（生成了什么、依据哪一版、结果如何），不记处置结论。每条失败的生成记录，以「镜号＋素材版次」为键，在问题台账中建立对应条目（台账条目回填生成记录编号，生成记录回填台账条目编号，双向可查）；诊断、处置定级与状态流以问题台账为准。处置轮次计数与台账合并计数（同一镜同一方案下 L1 与 L3 合计，沿用已确认结论 2 与整合稿 C3），GE 不得在生成记录里另计一套次数。台账条目关闭后，处置结果摘要回填生成记录的「处置指向」栏，生成记录至此闭合。
4. **存放**：生成记录表存项目目录「素材」子目录，与素材本体同级登记；素材本体不入 GitHub 仓库（文档头待解决问题 1），生成记录表属文本类对象，可入仓固定版本。

### 5.3 问题状态流（六态）

| 状态 | 进入条件 | 退出条件 |
| --- | --- | --- |
| 已登记 | 条目建立，字段 1–10 填写完整 | 开始根因诊断与处置定级 → 诊断中 |
| 诊断中 | 已开始诊断（按失败阶梯／审核口径定根因与处置级别） | 处置级别（字段 11）已定 → 处置中 |
| 处置中 | 处置动作执行中 | 处置执行完毕、字段 12 已填 → 待复验；轮次计数达上限仍不过 → 强制升级处置级别后继续处置中或转链级回流 |
| 待复验 | 处置完毕，等待按 04 文档 §4.2 三层范围复验 | 复验通过 → 已关闭或已升级；复验不过 → 退回处置中（轮次计数按字段 13 口径累加） |
| 已关闭 | 复验通过且复验记录（字段 15）完整，未触发检查项升级 | 终态 |
| 已升级 | 复验通过且复验记录完整，且本条目触发了前置检查项升级（同分类＋同根因累计 ≥2 次，字段 16 已回填升级去向） | 终态；此后同类问题应在前置检查阶段被拦截，若仍进入台账，按新条目登记并在问题描述中注明检查项失效，触发检查项修订 |

**关闭前置条件（硬规则）**：任何条目进入「已关闭」或「已升级」，必须先有完整的复验记录（字段 15：范围、结论、证据位置），无复验记录不得关闭（与 04 文档 §4.1「关闭的唯一依据是回归通过」同口径）。「已升级」不是跳过处置的出口——升级动作在条目走完处置与复验、关闭时执行，沉淀的是检查项，不是免除本条目的修复。

**与 04 文档问题单三态的映射**：04 文档 §4.1 的状态（开放／已回归通过／已关闭）是本六态的审核视图——开放＝已登记＋诊断中＋处置中；已回归通过＝待复验且复验结论为通过、待关闭确认；已关闭＝已关闭／已升级。两处表述指向同一状态流，不构成两套状态。

### 5.4 台账管理规则

- **一账到底**：审核问题、生成失败、成片验收问题不分账；M7 的问题台账即本台账（04 文档接口口径），GE 生成记录只回填条目编号、不另立失败账（§4.1）。
- **计数合并**：字段 13 的轮次计数全台账统一，任何来源、任何模块不得另计一套（整合稿 C3）。
- **升级纪律**：同类问题（同分类＋同根因）累计 ≥2 次自动升级为前置检查项（字段 16），升级在条目关闭时执行并留痕，不依赖人工想起（与 04 文档机制 6 同口径）。
- **随成片归档**：成片验收时，台账的关闭状态快照进入归档包（§六第 ⑥ 项）；归档时仍未关闭的条目必须有明确升级去向（Jason 裁决／下一轮首项／难度顶格报告），不许以「大部分已改」结案（04 文档 §4.3 同口径）。

### 6.2 版本对应表

归档包首页附版本对应表，逐项列明：成片文件版本号｜所依据的剧本版本｜分镜表版本｜声音设计表版本｜音色槽登记表版本｜人物设定卡版本｜场景道具设定卡版本｜锚点资产登记版本｜问题台账快照编号与时点｜成本计量记录编号。

**不予归档规则**：包内任一构成项的实际版本与版本对应表对不上，或与 ⑨ 登记表快照对不上，即不予归档。先查清是登记错误还是拿错了版本文件，更正后重新组包；不许带着对不上的版本对应表先行归档、事后补正（与 08 文档 S9 的版本错位验收口径联动）。

### 6.3 与第十项「发布与反馈登记位」的关系

九项（①–⑨）为归档包的原始构成，归档时必须齐全（⑥ 中未关闭条目按 §5.4 附升级去向的，不算构成缺失）。v1.1 新增的第十项「发布与反馈登记位」（§4.3）是归档之后追加的部分：归档时允许为空、注明待回填，发布后只追加编号回填，不改动九项构成与版本对应表。归档完整性按九项判定；登记位只查两件事——归档时有没有建位、回填编号与「反馈」子目录中的实际文件对不对得上（§4.3 第 4 条）。
